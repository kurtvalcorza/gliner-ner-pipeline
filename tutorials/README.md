## Conformance notes

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install or repository import. Section 2 carries the repository's 3 modules (`metrics.py`, `pipeline.py`, `samples.py`) verbatim in dependency order (each tagged `metadata.dimer.embedded_module`, collapsed, with one `# @title Infrastructure:` line; the only rewrites make `_WEIGHTS_ROOT` working-directory-relative and remove package-relative imports). Section 3 carries **two** manifests inline — the 3-file GLiNER snapshot and the 4-file mDeBERTa encoder snapshot — and asserts each against the module's identity constants before anything is fetched.
- **Runtime (RUN1, RUN10, ENV6; review GL-M1):** Section 1 does not pip-install into the kernel. It verifies a pinned `uv` wheel by size and SHA-256, has `uv` create a managed CPython 3.12.12 environment, installs the 50 packages of the carried hash-locked `requirements-colab.lock.txt` (compiled from the `pyproject.toml` pins, constrained to the versions of esm2-protein-pipeline's T4-passed lock) with `--require-hashes --only-binary :all:`, and routes every later cell to one persistent worker in that environment, so the kernel's pre-imported packages never need replacing and no restart should be needed. The lock holds manylinux x86_64 wheels: **Linux x86_64 runtimes only** (Colab, Kaggle, Linux Jupyter).
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifests or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Re-runs (DAT13, DAT14, EVAL8; GL-M2):** `adapt` changes the model in memory, so Sections 5 and 6 call `reset_to_pretrained()`, which reloads the verified snapshots when the model has been adapted; `GLiNERPipeline.adapt` refuses an adapted pipeline. Re-running from Section 4 reproduces the zero-shot baseline and the first-epoch loss.
- **BYOD (DAT10, DAT12, DAT19; GL-M3, GL-m5):** any label set (`BYOD_LABELS`, or every label in the file); a path (`BYOD_PATH`) on any runtime or the Colab upload; the record schema with an example, the minimum (14 records at `VAL_FRACTION = 0.25`, at least 4 per split) and the ceilings are printed before the upload; every label must occur in the training split; a cancelled upload, a missing path, a non-JSON file, spans written as objects, a label outside the declared set or a too-small dataset stop in Section 4 with a message naming the rule.
- **Evaluation (EVAL3, EVAL6, DAT8; GL-m3):** exact-span micro/macro P/R/F1 per label before and after adaptation on the 6 validation sentences, printed as a table and labelled tutorial evidence: one sentence template, the validation split also monitors training (no independent test split), and the baseline is prompted with snake-case label names that adaptation trains on.
- **Artifact (VER4, VER5, ART5; GL-m2):** the adapter `.pt` (format version 1.1) carries the trained tensors, a manifest of their names, shapes, dtypes and SHA-256, and both base revisions; `load_artifact` refuses an empty adapter, unknown tensor names, a shape or digest mismatch and a different base or encoder revision. Section 9 compares every adapter tensor and the predictions on every validation sentence plus the inference sentence.
- **Guided layer (GDL1–GDL14; GL-M4):** audience, task contract (Input → Model → Output), how-to-use, roadmap, observable objectives, six predictions, seven What-to-notice notes with collapsible worked answers (from this repository's CPU check), a Predict → Change → Run → Observe → Explain activity (Section 11: one epoch instead of three, with a `run_history` table), optional experiments, troubleshooting, glossary and a conclusion template; Sections 1–3 labelled Infrastructure and collapsed.
- **Score and threshold:** the span `score` is the model's uncalibrated span–label match score in [0, 1]; the decision rule is `score >= 0.5` (`DEFAULT_THRESHOLD`, upstream's default).
- **Expected warnings:** the cell after Section 3 prints `load_warnings` (in the CPU check: one SentencePiece byte-fallback `UserWarning`); the `fix_mistral_regex` message from `transformers` is a log line, not a captured warning.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a one-pass clean run recorded in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
