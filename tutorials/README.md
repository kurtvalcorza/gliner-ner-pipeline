## Conformance notes

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/gliner_ner_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the shared `_WEIGHTS_ROOT`, from which both snapshot directories derive, working-directory-relative), Section 3 carries **two** manifests inline — the 3-file GLiNER snapshot and the 4-file mDeBERTa encoder snapshot — and asserts each against the module's own identity constants before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the module's revision, its SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (two supply chains):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` and `stage_missing_encoder_files(ENCODER_WEIGHTS_DIR, allow_download=True)` fetch only the manifest entries that are absent, each from the Hugging Face Hub at its own immutable revision (never `main`); `verify_snapshot` and `verify_encoder_snapshot` re-hash every entry; `GLiNERPipeline.from_pretrained(weights_dir=..., encoder_dir=...)` then loads with the library's `config.model_name` redirected to the verified encoder directory (`local_files_only=True`), so no tokenizer or config is resolved from the Hub or an HF cache. The notebook's only external dependencies are the pinned PyPI distributions and the Hub at those two revisions. It never imports `gliner`, `transformers` or `huggingface_hub` for model work outside the carried module cell.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/gliner_ner_input_manifest.json` with the schema, ceilings, the text's observed character and word counts, the label set, the threshold, the verdict, **both** pinned identities, and one recorded rejection finding from the duplicate-label probe; `evaluation_report` (EVAL21) writes `outputs/gliner_ner_evaluation_report.json` — `not-measurable` on the synthetic sample (with what labelled data would make the task measurable), `sample-sanity` with the repository's own `entity_f1` when `GOLD_JSON` supplies gold spans.
- Score and threshold semantics (UNC1/UNC2/UNC3/UNC4): the span `score` is a per-span confidence in [0, 1], not a calibrated probability; the only decision rule is `score >= threshold`, with the upstream default 0.5 exposed as a form field and owned by the caller.
- Metric (EVAL1/EVAL7/EVAL9): `entity_f1` (exact-span micro P/R/F1) is the repository's only metric helper and applies only when gold spans exist; the synthetic sentence ships none, so the default path's verdict is `not-measurable`. Recorded `SHOULD` deviation: EVAL11 (the trivial no-entity baseline has F1 = 0 by construction and is not reported).
- Ceilings `MAX_TEXT_CHARS`, `MAX_LABELS`, `MAX_LABEL_CHARS`, label uniqueness and the threshold range are printed before the model runs; the library's silent 384-word cut is stated and the word count printed (DAT22/DAT23).
- The expected transformers `fix_mistral_regex` warning is documented in the prerequisites and printed from `pipe.load_warnings` so the learner can recognise it.
- The default sample is synthetic text with invented names; `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
